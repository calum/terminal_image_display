# termage

Show images, animated gifs and videos in a terminal using 16 ANSI colours,
written in Rust. A library (`termage`) and a command line tool (`termage`) that
is a thin wrapper around it. Built on the `terminal_graphics` crate.

## Non-negotiable rules

1. **Rust only.** Source, tests, examples and tooling are all Rust. Do not add
   HTML, CSS, JavaScript, shell or Python files. The website is *generated from
   Rust* (`examples/build_site.rs` holds the page, style and script as strings),
   and its sample pictures and screenshots are generated by Rust examples.
   `tests/pure_rust.rs` enforces this; CI fails if it breaks. The only non-Rust
   files allowed are config, docs and the images listed in that test's
   allow-list.
2. **TDD, always.** No production code without a failing test first:
   - RED: write one test for one behaviour, run it, confirm it fails for the
     expected reason.
   - GREEN: write the minimum code to pass.
   - REFACTOR: clean up with the suite green.
   Bug fixes start with a test that reproduces the bug.
3. **Follow the test triangle** (many fast tests at the bottom, few at the top):
   - **Unit tests** (the bulk): `#[cfg(test)] mod tests` beside the code in
     `src/`. Pure logic and no I/O: scaling (`fit`), colour picking, dithering,
     argument and header parsing, frame reading.
   - **Integration / end-to-end tests** (some): `tests/e2e.rs` runs the real
     `termage` binary on generated files (and a throwaway local HTTP server) and
     checks stdout, stderr and the exit status.
   - **Doc tests** on public items are a bonus layer, not a substitute. The
     README's ```` ```rust ```` blocks are compiled too, so keep them working.
4. **Keep it testable.** Drawing goes to any `impl Write`, never straight to
   stdout, so tests capture it as bytes. Pure functions (`fit`, `pick_size`,
   `to_display`, `delay_of`, `parse_probe`, `read_frames`) hold the logic; the
   code that touches the outside world (files, sockets, `ffmpeg`, the terminal)
   stays thin.
5. **Never panic or hang on bad input.** A missing file, a file that is not an
   image, a failed download, a missing `ffmpeg`, a zero-size terminal, a
   closed pipe: each is an `Error` (or a clean exit for `BrokenPipe`), reported
   as one line on stderr with exit status 1. No `unwrap` or `expect` on anything
   a user can influence.
6. **Semver from here on.** A breaking library change needs a major version bump
   and a CHANGELOG migration table. Anything that changes `Options`, a public
   signature or an error variant counts. Merging a version bump to `master`
   publishes to crates.io (see Releasing); a merge that leaves `version`
   unchanged never publishes.

## Commands

```
cargo test --all-targets && cargo test --doc   # everything
cargo test --no-default-features --all-targets # the website's build (no `net`)
cargo clippy --all-targets                      # must be warning-free
cargo fmt --all
cargo llvm-cov --fail-under-lines 85            # coverage gate (CI)

cargo run -- docs/samples/crab.png --dither     # try the tool

# the website
cargo build --release --example web --no-default-features --target wasm32-unknown-unknown
cargo run --example build_site                  # writes target/site

# regenerate the pictures
cargo run --release --example make_samples      # docs/samples
cargo run --release --example render_gif -- docs/samples/sunset.jpg docs/screenshots/sunset.png 120 38 5 --dither
```

CI runs with `RUSTFLAGS=-D warnings`, so warnings (and rustdoc warnings) are
errors. Video tests need `ffmpeg` and `ffprobe`; without them they print
"skipped" and pass, and CI installs ffmpeg so they run for real.

## Layout

- `src/lib.rs` - crate docs, `Options`, `show` / `show_image` / `play`,
  `pick_size`, root re-exports, README doc-test
- `src/render.rs` - `fit` and `to_display` / `to_display_dithered`: scale an
  image and turn it into a `terminal_graphics::Display` of half-block cells
  (each cell is a `▄`: lower pixel as foreground, upper pixel as background)
- `src/load.rs` - decode bytes into images and gif `Frame`s (`flatten` blends
  transparency onto black)
- `src/source.rs` - read a file or download a URL (`net` feature)
- `src/video.rs` - video through `ffmpeg` / `ffprobe` (raw RGB over a pipe)
- `src/error.rs` - `Error` (`Io`, `Image`, `Download`, `Video`)
- `src/bin/main.rs` - the CLI (clap); size defaults come from `pick_size`
- `src/bin/update/mod.rs` - `--update` and the once a day new version reminder
  (`TERMAGE_NO_UPDATE_CHECK` turns it off, `TERMAGE_UPDATE_BASE` points it at a
  mirror for tests)
- `examples/web.rs` - the library as WebAssembly (C-style exports) for the site
- `examples/build_site.rs` - generates the website into `target/site`
- `examples/make_samples.rs`, `examples/render_gif.rs` - draw the samples and
  screenshots in `docs/`
- `tests/e2e.rs`, `tests/pure_rust.rs` - end-to-end and repo hygiene tests
- `docs/samples` (inputs) and `docs/screenshots` (what the terminal shows) are
  committed images; the README and the website use them
- `README.md`, `CHANGELOG.md` - every user-visible change goes in the CHANGELOG,
  breaking ones with a migration row

## Conventions

- Edition 2021, `#![forbid(unsafe_code)]`, `#![warn(missing_docs)]`: every public
  item gets a `///` comment, with a runnable example where it helps.
- Naming: no `get_` prefixes, constructors are `new`, `with_*` builders consume
  `self`. `Options` is `#[non_exhaustive]`: add settings as fields plus a
  `with_*` method.
- Network access sits behind the default `net` feature so the library builds for
  `wasm32-unknown-unknown` with `--no-default-features`. Anything that needs
  sockets or processes must not leak into the code the website uses.
- The website's terminal must behave like the real tool: it calls the same
  `to_display` code through `examples/web.rs`. Do not reimplement scaling or
  colour picking in the page's script.
- Examples are not part of the published crate (`exclude` in `Cargo.toml`).
- Screenshots are made by the tool itself (`render_gif`), never by hand, and the
  samples are drawn by code, so there are no photos to license.

## Releasing

Bump `version` in `Cargo.toml` (and add a CHANGELOG section) in the PR. When it
reaches `master`, `.github/workflows/ci.yml` publishes to crates.io with the
`CARGO_REGISTRY_TOKEN` secret and tags `vX.Y.Z`, after the tests and coverage
pass. A merge with an already-published version skips publishing.
The same workflow then builds `termage-<target>` programs for five targets and
creates a GitHub release for the tag with them and `SHA256SUMS`; a version
that already has a release is skipped. Those file names are a contract with
`src/bin/update/mod.rs` (`asset_name`, used by `--update`) and the install
scripts in `examples/build_site.rs`: change all three together.
The install scripts are generated by `build_site` and deployed with the website,
so shell and PowerShell stay out of the repo as files.
`.github/workflows/pages.yml` redeploys the website on every push to `master`;
it needs Settings > Pages > Source set to "GitHub Actions".
